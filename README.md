# FLARE 2026

Статический адаптивный сайт премии FLARE 2026. HTML/CSS/JS без npm, сборщика и серверного приложения. Голоса, пользовательские PIN-хэши и привязка email хранятся в Supabase; публичная часть сайта не имеет доступа к таблицам напрямую.

## Что уже реализовано

- Полноэкранное вступление с оригинальными лучами и логотипом FLARE; ссылки прокручивают к голосованию, а через 1,5 секунды открывают список выбранной категории после входа. Шапка появляется только после исчезновения логотипа, не перекрывает модальные окна и плавно скрывается при входе в FAQ.
- 18 номинаций со списком номинантов, каталогом прошлого года, каруселью победителей с ручным управлением и выбором голосов.
- Email + PIN аккаунты на Supabase RPC; повторный вход, привязка нескольких разрешённых email к одному участнику, голос за себя заблокирован на клиенте и сервере.
- Профиль участника с аватаром из номинантов, статистикой, скрытым email с отдельным просмотром владельцем, фотобаннером, рамками и редкими бейджами. Мини-игра BOING! сохраняет рекорды, COINS, улучшения, покупки, имена BOB и таблицу лидеров на сервере. До начала раунда можно нарисовать круглому BOB лицо, а после покупки `bob-face-upload` за 10 000 COINS — загрузить свою PNG; оно сохраняется как PNG и показывается вместе с именем BOB в публичном профиле, открывающемся по нику из LEADERS. Магазин разделён на апгрейды, косметику и улучшения профиля. Надетые бейджи показываются сверху иконками с подсказками, карандаш рядом с ними открывает нижнюю коллекцию для снятия/возврата с отдельным окном снятых и сохранением зелёной галочкой; Eozik получает бейдж тестировщика, Maronnix — бейдж создателя.
- Сохранение и редактирование голосов до 21 ноября 2026, опрос о дате премии и панель Maronnix со вкладками голосования, опроса, статистики и дизайна.
- GitHub Actions публикует статические файлы на GitHub Pages без сборки. Секретный `service_role` ключ никогда не нужен в браузере.

## Запуск — один раз настроить Supabase

1. Создай проект в Supabase. В **SQL Editor** выполни файл [`supabase/schema.sql`](supabase/schema.sql) целиком. Схема создаёт закрытые таблицы, RPC-функции и полный каталог номинаций/номинантов. При последующих обновлениях сайта, затрагивающих RPC, повторно выполни этот же файл: он обновляет функции и безопасно синхронизирует каталог без удаления голосов или аккаунтов. Для уже работающего проекта примени новые SQL-миграции из `supabase/migrations/` по порядку; в частности, `20261105_account_nominee_view_preference.sql` добавляет безопасное сохранение выбранного вида списка номинантов в аккаунте, `20261105_profiles_and_boing.sql` — профили, BOING!, магазин, рекорды и бейджи, `20261106_bob_faces_public_profiles.sql` — PNG-лица BOB, публичные профили и покупку видимости имени BOB в LEADERS, а `20261106_bob_png_face_uploads.sql` — покупку загрузки собственных PNG, `20261106_profile_badge_layout.sql` — атомарное редактирование надетых бейджей. Для работы нового профиля, BOING! и редактора бейджей все четыре BOING-миграции нужно обязательно применить в Supabase SQL Editor. Новая версия выдаёт участнику только агрегаты опроса после его собственного ответа; персональные ответы по-прежнему доступны только организатору. Закрытая RPC-функция `admin_summary` также формирует статистику по регистрациям и голосам организатора без email-адресов.
2. В **Table Editor → flare_authorized_emails** приватно добавь по одной строке для каждого выданного организатором адреса: `email` и соответствующий `expected_nickname`. Поле `account_id` оставь пустым — Supabase сохранит SQL `NULL`; не вводи туда текст `NULL` и не указывай UUID вручную. Система сама заполнит `account_id` при первой успешной регистрации/авторизации участника и привяжет к аккаунту остальные разрешённые адреса с тем же `expected_nickname`. Не добавляй email-список в публичный репозиторий. Эта закрытая таблица определяет, какие адреса допускаются и какой ник назначается автоматически.
3. Пользователь вводит только email и PIN — поля выбора ника нет. Если это разрешённый email и участник ещё не регистрировался, аккаунт создаётся автоматически с `expected_nickname`, закреплённым за email в Supabase. Если аккаунт уже существует, тот же PIN проверяется и вход выполняется в него. Дополнительные разрешённые email того же участника используют тот же PIN и привязываются к этому аккаунту. Любой email вне allowlist получает такой же общий отказ, как и неверный PIN; список разрешённых адресов через интерфейс не раскрывается.
4. В **Project Settings → API** возьми Project URL и публичный `anon`/`publishable` key. Вставь их в `config.js` вместо `YOUR_SUPABASE_PROJECT_URL` и `YOUR_SUPABASE_ANON_KEY`. Это публичный ключ с ограниченными правами; **никогда** не вставляй `service_role`.
5. Убедись, что в Supabase API доступна схема `public` (обычно значение по умолчанию). В настройке CORS/allowed origins разреши домен GitHub Pages проекта, если в настройках проекта ограничен список origin.
6. В GitHub открой **Settings → Pages** и укажи **Source: GitHub Actions**. Окружение `github-pages` должно разрешать ветку `arena/7360ef95-flare-2026-official` в **Settings → Environments → Deployment branches**. Workflow выкладывает изменения прямо из этой ветки, без слияния в `main`. Для ручного запуска доступен **Actions → Publish FLARE 2026 to GitHub Pages → Run workflow**.

## Важно перед рассылкой ссылки

- Сайт намеренно не содержит email-список участников; он должен храниться только в приватной базе Supabase. Заранее добавь адреса из предоставленного списка в `flare_authorized_emails` и убедись, что Maronnix зарегистрирован именно на нужный организаторский email.
- Вкладка «Дизайн» хранит заменённые фото только в IndexedDB текущего браузера и умеет скачать ZIP с файлами по их путям в `assets/photos/`. Аватары показываются в круглом предпросмотре как у номинантов; их можно двигать мышью/пальцем, точно настраивать по осям и увеличивать, а итоговый квадратный кадр используется и на сайте, и в ZIP. Чтобы опубликовать фото для всех, распакуй архив в корень репозитория и отправь эти файлы в GitHub.
- Уведомления email и восстановление PIN не предусмотрены: организатор должен проверять адреса при их добавлении. Если PIN потерян, организатору потребуется безопасно сбросить `pin_hash` по процедуре вне публичного интерфейса.
- Supabase anon key включён в клиентский config по дизайну; защита основана на закрытых таблицах, отозванных прямых правах, RPC-проверке индивидуальной сессии и PIN. Сервисный ключ остаётся только в панели Supabase.
- Обычный ответ профиля содержит только маскированный email; полный адрес возвращает отдельная RPC владельцу действующей сессии. Публичный профиль из LEADERS не содержит email, инвентаря или активного раунда. Лицо BOB — прозрачный PNG до 150 КБ; оно загружается с профилем и не пересылается в частых ответах синхронизации раунда. Рисование доступно без покупки. Загрузка своей PNG принимает файл до 12 МБ, кадрирует его в круг и уменьшает до общего лимита; отдельный RPC `upload_my_boing_face` проверяет наличие купленного `bob-face-upload`. Имя BOB в LEADERS видно только после покупки `leader-bob-name`, а в публичном профиле — всегда. Для фотобаннера браузер принимает JPG, PNG или WebP до 12 МБ, преобразует изображение в JPEG до 500 КБ и не принимает GIF/SVG/видео. COINS начисляются за новые сотни общих очков BOING!: 100, после 1 000 — 150, после 10 000 — 300, после 50 000 — 500, после 100 000 — 1 000; улучшение COIN BOOST увеличивает награду на 20% за уровень.
- Названия и ссылки всех видео-номинантов меняются в админ-панели → «Дизайн» → «Ссылки и названия видео». Для YouTube-видео кнопка воспроизведения открывает встроенный плеер поверх номинации; само видео запускается вручную кнопкой плеера, другие видео-ссылки открываются в новой вкладке. Чтобы временно отключить встроенный плеер и вернуть прежнее поведение, установи `inlineYoutubePlayerEnabled: false` в `config.js`. Для управления ссылками и типа видео у варианта «Eozik, Flourin, Maronnix vs Denis_185, Fines Stark» нужна актуальная схема `supabase/schema.sql` в Supabase SQL Editor.
- После окончания голосования таймер отсчитывает до даты церемонии, победившей в опросе (при ничьей — до самой ранней из связанных дат), а затем переключается на публикацию итогов 6 декабря. В этот день сайт показывает карточки победителей основных и дополнительных номинаций. Для публичной публикации агрегированных итогов нужно выполнить актуальный `supabase/schema.sql` в Supabase SQL Editor; RPC даты возвращает только победившую дату (или даты при ничьей), а RPC победителей доступен лишь с 6 декабря. Данные и личности отдельных проголосовавших публично не раскрываются.
- Голосование доступно весь день 21 ноября 2026 и закрывается в 00:00 22 ноября по Москве. Страница и сервер закрывают приём голосов в этот момент и оставляют результаты владельцу аккаунта для просмотра.

## Локальный просмотр

Открой `index.html` в браузере или подними статический сервер, например `python3 -m http.server 8000`. Голосование станет доступно после настройки Supabase и `config.js`.
