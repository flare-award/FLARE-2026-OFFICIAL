# FLARE 2026 — сайт голосования

Одностраничный статический сайт без сборщика и зависимостей для посетителя: обычные HTML, CSS и JavaScript. Шрифты Michroma и Manrope хранятся локально, поэтому интерфейс не зависит от Google Fonts. Номинации открываются даже до подключения базы, а учётные записи и голоса проходят только через защищённые RPC-функции Supabase.

## Публикация на GitHub Pages

В репозитории уже настроен GitHub Actions workflow: **после push в `main` или в ветку `arena/62d09ade-flare-2026-official` он сразу публикует папку `public/`**, без `npm install`, сборки и ручной загрузки файлов. Публикация из Arena-ветки не требует слияния в `main`; она будет обновлять тот же адрес GitHub Pages. Для `main` используется защищённое окружение `github-pages`, для Arena-ветки — отдельное `github-pages-arena`, поскольку защита основного окружения разрешает только `main`.

Один раз включите источник публикации:

1. Откройте **Settings → Pages** репозитория.
2. В разделе **Build and deployment** выберите **Source: GitHub Actions**.
3. После push в `main` или `arena/62d09ade-flare-2026-official` дождитесь успешного workflow **Deploy FLARE 2026 to GitHub Pages** во вкладке **Actions**. Оба варианта обновляют сайт по ссылке из Settings → Pages.

Повторно публиковать сайт вручную не нужно. Workflow также можно запустить кнопкой **Run workflow**.

## Подключение Supabase (обязательно для настоящего голосования)

Нужен свой проект Supabase: база и ключи принадлежат организатору, поэтому подключить голосование без этих данных невозможно.

1. В Supabase откройте **SQL Editor**, вставьте целиком [`supabase/setup.sql`](supabase/setup.sql) и запустите запрос. Скрипт создаёт каталог номинаций, таблицы, включает RLS без прямых публичных политик, настраивает RPC для входа и голосования, ограничения самоголосования и стартовые данные.
2. Откройте **Project Settings → API**. В [`public/config.js`](public/config.js) заполните только `supabaseUrl` и публичный `anon` / `publishable` key:

   ```js
   window.FLARE_CONFIG = {
     supabaseUrl: "https://YOUR_PROJECT_REF.supabase.co",
     supabaseAnonKey: "ВАШ_PUBLIC_ANON_ИЛИ_PUBLISHABLE_KEY"
   };
   ```

   Этот файл будет виден посетителям — так и должно быть для публичного ключа. **Никогда не вставляйте сюда `service_role` key, пароль базы или другой секрет.** Доступ ограничен RLS, а операции с голосами доступны только через проверяемые сервером RPC.
3. Сохраните и отправьте изменения в `main`. GitHub Actions обновит сайт автоматически.

До подключения Supabase сайт показывает каталог номинаций в режиме просмотра и явно сообщает, что голосование не подключено. Никаких фальшивых голосов в `localStorage` не создаётся.

## Аккаунты и права

- При первой регистрации участник выбирает свой email, ник из списка и PIN из 4–32 латинских букв/цифр. В таблице сохраняется bcrypt-хэш PIN, а не сам PIN. Рекомендуйте участникам выбирать длинный PIN.
- Email-коды и OAuth намеренно не используются. **Без подтверждения email невозможно доказать владельца адреса.** Сайт рассчитан на доверенное сообщество; не используйте такую схему для публичной или чувствительной системы.
- Один ник привязывается только к одному аккаунту. Повторный email и дополнительные адреса надо привязать вручную в SQL Editor. Например, чтобы добавить второй адрес к аккаунту Nodben:

  ```sql
  insert into public.flare_emails (email, account_id)
  select lower('дополнительный@example.com'), id
  from public.flare_accounts
  where lower(nickname) = lower('Nodben')
  on conflict (email) do update set account_id = excluded.account_id;
  ```

  Если такой адрес ранее создал отдельный аккаунт, сначала проверьте его запись: перенос email — решение организатора.
- Для выдачи панели организатора участнику **Maronnix** сначала зарегистрируйте его профиль, затем выполните:

  ```sql
  update public.flare_accounts
  set is_admin = true
  where lower(nickname) = lower('Maronnix');
  ```

  Права проверяются ещё раз на сервере; одно только изменение интерфейса не открывает результаты. Обновите страницу или войдите заново, чтобы обновить права сессии. Аккаунт Maronnix голосует так же, как остальные.
- Другие участники не могут читать таблицы аккаунтов и голосов напрямую. Панель Maronnix показывает сводку и детали голосов, включая ник проголосовавшего; экспорт CSV доступен только в этой панели.
- Вход ограничен восемью неудачными PIN-попытками на email за 15 минут. Сессии имеют случайный токен с 30-дневным сроком, в Supabase хранится только его хэш.

## Данные и дедлайны

- Номинации и карточки редактируются в [`public/data.js`](public/data.js); их идентификаторы должны совпадать с каталогом в `supabase/setup.sql`. После изменения структуры повторно запустите seed-часть/скрипт целиком **до начала голосования**. Не удаляйте номинантов и идентификаторы после появления голосов.
- Реальные победители FLARE 2025 в исходных данных не указаны. Поэтому раздел архива сейчас показывает аккуратное состояние ожидания, не приписывая победу случайным людям. Чтобы заполнить карусель, добавьте записи в `previousWinners` в `public/data.js`, например:

  ```js
  previousWinners: [
    { year: "2025", award: "FLARE KING", winner: "Ник победителя", caption: "Главная легенда года" },
    { year: "2025", award: "ИГРА ГОДА", winner: "Название игры", caption: "Выбор сообщества" }
  ]
  ```

  Карусель сама включит автопрокрутку раз в 4,8 секунды; ручное нажатие сбрасывает таймер, быстрые двойные шаги блокируются на время анимации.
- Для видео укажите `videoUrl: "https://…"` в карточке соответствующего номинанта. Плей-кнопка откроет ссылку в новой вкладке. Пока URL пустой, карточка отображается, а плей-кнопка объясняет, что ссылку добавит организатор.
- Дедлайн хранится в двух местах: `ballotDeadline` в `public/data.js` и константа `2026-11-22 00:00:00+05:00` в SQL-функции `flare_cast_vote` в `supabase/setup.sql`. При переносе сроков обновляйте оба значения. Сейчас приём заканчивается **21 ноября 2026, 23:59 по Екатеринбургу (UTC+5)**. Дата премии — 5 декабря 2026.
- Чтобы добавить участника для регистрации, добавьте его ник в `participants` в `public/data.js` и строку в `flare_participants` в Supabase. Сверяйте имена с `personNickname`: именно по аккаунту определяется запрет самоголосования.

## Локальный просмотр

Сборка не нужна. Для корректной загрузки локальных файлов используйте любой статический сервер, например:

```bash
python3 -m http.server 8080 --directory public
```

После этого откройте `http://localhost:8080`. Для проверки входа и голосования должны быть настроены Supabase и `public/config.js`.
