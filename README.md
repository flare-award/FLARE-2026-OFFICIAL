# FLARE 2026

Статический адаптивный сайт премии FLARE 2026. HTML/CSS/JS без npm, сборщика и серверного приложения. Голоса, пользовательские PIN-хэши и привязка email хранятся в Supabase; публичная часть сайта не имеет доступа к таблицам напрямую.

## Что уже реализовано

- Главная премиального стиля, адаптивная сетка и анимированная вспышка; FAQ в отдельной тёмной зоне.
- 18 номинаций со списком номинантов, каталогом прошлого года, автопрокруткой карусели и выбором голосов.
- Email + PIN аккаунты на Supabase RPC; повторный вход, привязка нескольких разрешённых email к одному участнику, голос за себя заблокирован на клиенте и сервере.
- Сохранение и редактирование голосов до 21 ноября 2026, финальное подтверждение полного бюллетеня, опрос о дате премии и панель Maronnix.
- GitHub Actions публикует статические файлы на GitHub Pages без сборки. Секретный `service_role` ключ никогда не нужен в браузере.

## Запуск — один раз настроить Supabase

1. Создай проект в Supabase. В **SQL Editor** выполни файл [`supabase/schema.sql`](supabase/schema.sql) целиком. Схема создаёт закрытые таблицы, RPC-функции и полный каталог номинаций/вариантов.
2. В **Table Editor → flare_authorized_emails** добавь по одной строке на каждый email из списка участников, указав `email` и закреплённый за ним `expected_nickname`; `account_id` оставь `NULL`. Не добавляй адреса в публичный репозиторий — это персональные данные. Привязка email к конкретному нику проверяется сервером, поэтому пользователь не может зарегистрироваться под чужим ником.
3. Участник при первом входе выбирает закреплённый ник и задаёт PIN (латиница/цифры, 4–72 знака). Первый email автоматически создаёт аккаунт; остальные разрешённые email этого же ника привяжутся к нему, только если указан тот же PIN. Вручную искать UUID и допривязывать дополнительные почты не нужно.
4. В **Project Settings → API** возьми Project URL и публичный `anon`/`publishable` key. Вставь их в `config.js` вместо `YOUR_SUPABASE_PROJECT_URL` и `YOUR_SUPABASE_ANON_KEY`. Это публичный ключ с ограниченными правами; **никогда** не вставляй `service_role`.
5. Убедись, что в Supabase API доступна схема `public` (обычно значение по умолчанию). В настройке CORS/allowed origins разреши домен GitHub Pages проекта, если в настройках проекта ограничен список origin.
6. В GitHub открой **Settings → Pages** и укажи **Source: GitHub Actions**. После публикации изменений в ветку `arena/7360ef95-flare-2026-official` workflow скопирует только пять статических файлов и развернёт сайт — публикация идёт прямо из этой ветки, без ожидания слияния в `main`. Для ручного запуска доступен **Actions → Publish FLARE 2026 to GitHub Pages → Run workflow**.

## Важно перед рассылкой ссылки

- Сайт намеренно не содержит email-список участников; он должен храниться только в приватной базе Supabase. Заранее добавь адреса из предоставленного списка в `flare_authorized_emails` и убедись, что Maronnix зарегистрирован именно на нужный организаторский email.
- Уведомления email и восстановление PIN не предусмотрены: организатор должен проверять адреса при их добавлении. Если PIN потерян, организатору потребуется безопасно сбросить `pin_hash` по процедуре вне публичного интерфейса.
- Supabase anon key включён в клиентский config по дизайну; защита основана на закрытых таблицах, отозванных прямых правах, RPC-проверке индивидуальной сессии и PIN. Сервисный ключ остаётся только в панели Supabase.
- Ссылки на клипы пока не ведут на несуществующие видео: интерфейс показывает, что материалы добавит организатор. Когда ссылки будут готовы, добавь свойство `url: 'https://…'` в нужные объекты `clip-of-year` в `data.js`; кнопка play откроет ссылку в новой вкладке.
- Рабочий срок голосования задан как 21 ноября 2026, 23:59:59 по Москве. Текущая версия страницы закрывается автоматически после этой даты и оставляет результаты голосов владельцу аккаунта для просмотра.

## Локальный просмотр

Открой `index.html` в браузере или подними статический сервер, например `python3 -m http.server 8000`. Голосование станет доступно после настройки Supabase и `config.js`.
